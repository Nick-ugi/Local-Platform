# Week 7 Place Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 방문자가 Explore에서 장소를 Category별로, 가까운 순으로 훑고, 검색하고, 상세에서 전화 · 웹사이트 · 길찾기 · 공유를 쓰고, "View on map"으로 지도의 그 장소로 간다. 상세 페이지는 검색엔진과 공유 링크의 도착점이 된다.

**Architecture:** Backend에 목록과 검색을 함께 맡는 `GET /places` 하나를 더한다. Explore와 Search는 서버가 Queenstown 중심 기준으로 그린 목록을 먼저 내려주고, 위치를 쓸 수 있는 브라우저에서만 같은 쪽을 위치 기준으로 다시 받아 바꾼다. 목록의 상태(Category, 검색어, 쪽)는 URL에 있고 위치는 URL에 넣지 않는다. "View on map"은 지도의 위치를 미리 저장하고 `/?place={slug}`로 간다. Seed 데이터는 CSV 한 파일과 그것을 DB에 올리는 SQL로 둔다.

**Tech Stack:** Spring Boot 4.0, MyBatis, PostGIS / Next.js 16, next-intl, Vitest

**Spec:** [docs/01-mvp-feature-definition.md](../01-mvp-feature-definition.md) (PLACE-01 ~ PLACE-06, SEARCH-01 ~ SEARCH-02, COMMON-01, COMMON-02, COMMON-05, SEO-01의 Place), [docs/02-information-architecture.md](../02-information-architecture.md) 3장, 4장, 6장, [docs/03-user-flow.md](../03-user-flow.md) (UF-01, UF-03, UF-04, UF-07, 상태 안내), [docs/04-wireframe.md](../04-wireframe.md) (m-explore, m-search, m-place, d-explore, d-place), [docs/06-api-specification.md](../06-api-specification.md) 1장, 4장. 캘린더 7주차의 완료 기준은 "장소 검색 → 목록 → 상세 → 지도 이동 흐름 완료"다. 6주차에서 넘어온 것: 검색창, Explore 목록, 상세의 "View on map".

## Global Constraints

- 목록 응답은 `{ items, page, size, total }`이다. `page`는 기본 1(1 이상), `size`는 기본 20(1 ~ 50)이다. 값이 없는 필드는 생략하지 않고 `null`로 준다.
- `/places`는 항상 가까운 순이다. 위치(`lat`, `lng`)를 보내면 그 위치 기준이고 `distanceM`을 채운다. 보내지 않으면 Queenstown 중심(`-45.0312`, `168.6626`) 기준이고 `distanceM`은 `null`이다.
- 서비스 지역 안인지는 클라이언트가 판단한다. 지역 밖이거나 권한이 없으면 위치를 보내지 않고, 거리를 표시하지 않는다.
- Web은 화면에 들어올 때 위치 권한을 묻지 않는다. "Use my location"을 누를 때 묻는다. 이전에 허용한 방문자는 묻지 않고 쓴다.
- API에 보내는 위치는 소수 넷째 자리로 반올림한다(약 11m). 위치를 화면의 URL에 넣지 않는다.
- Explore의 Category는 하나만 고른다. URL은 `/explore/{category}`다. Search는 `/search?q={keyword}`이고 Place만 찾으며 검색에 노출하지 않는다.
- 상세 화면에는 지도를 넣지 않는다. "View on map"은 `/?place={slug}`로 간다.
- 전화번호나 웹사이트가 없으면 그 버튼을 표시하지 않는다. 출처와 수정일은 항상 표시한다.
- 문구는 `web/messages/en.json`에 둔다. 폭에 따른 배치는 768px 기준의 CSS(`md:`)로만 처리한다. 누르는 대상은 44px 이상이다.
- 브라우저는 같은 주소의 `/api/v1/...`를 부른다. 서버에서 그리는 화면은 Backend를 바로 부른다.
- 404가 나올 수 있는 경로(`/explore`, `/search`, `/places`)에는 `loading.tsx`를 두지 않는다. 두면 없는 페이지가 200으로 응답한다.
- 한 번 공개한 `slug`는 바꾸지 않는다. Seed를 다시 올려도 `slug`로 같은 행을 고친다.
- 검증과 커밋을 한 명령에 묶을 때는 테스트, Lint, 타입 검사가 모두 통과했을 때만 커밋되게 한다(`&&`). 파일은 Write 도구로 쓴다.
- 커밋 메시지는 영어, 마지막 줄에 `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`를 붙인다.

## Review Focus

1. **검색어가 평범하지 않다.** `%`, `_`, `\`, 따옴표, 공백뿐인 값, 아주 긴 값이 와도 500이 아니어야 하고, `%`와 `_`는 글자 그대로 찾아야 한다. → Task 1, Task 5
2. **URL의 쪽 값이 이상하거나 끝을 넘는다.** `?page=0`, `abc`, `999`가 빈 화면이나 오류 화면이 아니라 404여야 한다. → Task 1, Task 3
3. **위치가 늦게 오거나, 위치 기준 요청이 겹치거나 실패한다.** 먼저 보낸 요청의 답이 나중 것을 덮어쓰면 안 되고, 실패해도 서버가 준 목록은 남아 있어야 한다. → Task 4
4. **Place의 값이 비었거나 위험하다.** `javascript:`로 시작하는 웹사이트, 숫자가 아닌 전화번호, 열리지 않는 이미지 주소가 버튼이나 깨진 그림이 되면 안 된다. → Task 7
5. **공유 기능이 없는 브라우저다.** Web Share도 클립보드도 못 쓰는 환경(http로 연 개발 주소 등)이거나 방문자가 공유를 취소해도 오류가 나지 않고 할 일을 알려야 한다. → Task 7

- `Paging.of`: `page`가 1보다 작으면 `ApiException.invalid("page", "must be 1 or greater")`, `size`가 1 ~ 50 밖이면 `ApiException.invalid("size", "must be between 1 and 50")`.

  - `lat`, `lng` 중 하나만 있으면 없는 쪽의 이름으로 `invalid(…, "is required with lat")` / `"is required with lng"`. 둘 다 있으면 `Ranges.requireWithin("lat", lat, 90)`, `("lng", lng, 180)`.

Category 조건과 낱말 조건은 값이 있을 때만 건다. 낱말 하나는 `(name ILIKE #{w} ESCAPE '\' OR description ILIKE … OR address ILIKE …)`이고 낱말끼리는 `AND`다. 정렬은 `docs/05-erd.md` 8장의 `ST_Distance`(기준은 보낸 위치, 없으면 Queenstown 중심) 다음에 `id`다. `distance_m`은 위치를 보냈을 때만 `round(...)::int`, 아니면 `NULL`이다.
