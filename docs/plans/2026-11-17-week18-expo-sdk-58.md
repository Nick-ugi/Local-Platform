# Week 18 Expo SDK 58 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** App을 Expo SDK 58로 올려 17주차에 남긴 npm 권고(expo-router의 `query-string`, Expo 빌드 도구의 `minimatch`)를 고치고, Play 내부 테스트 전에 지금 SDK에 맞춘다.

**Architecture:** 화면과 동작은 바꾸지 않는다. 버전을 올리고, SDK 58의 변경 때문에 깨지는 곳만 고친다. `android/`는 Continuous Native Generation이라 새로 만든다.

**Tech Stack:** Expo SDK 58 (React Native 0.88, React 19.3.0 — Web · Admin과 같은 버전), expo-router 58, @rnmapbox/maps 10, jest-expo 58.

**Spec:** [Expo SDK 58 changelog](https://expo.dev/changelog/sdk-58)와 17주차 `npm audit`(21건: low 9, moderate 9, high 3; production 6건 — high 3 `decode-uri-component` · `query-string` ← expo-router 57, moderate 3 `minimatch` ← `@expo/fingerprint`).

SDK 58에서 이 앱에 닿는 변경:

- React Native 0.87의 Strict TypeScript API가 기본(`react-native/Libraries/*` 깊은 import 금지, ref 타입이 `ViewInstance` 같은 인스턴스 타입). 지금 코드에는 깊은 import가 없다. 없어진 API(`InteractionManager`, `Touchable`, `StatusBar`의 `backgroundColor` · `translucent` 등)도 쓰지 않는다.
- expo-router의 navigation core가 바뀌었다(`expo-router/react-navigation` import, custom navigator). 이 앱은 `Stack`과 `Tabs`만 쓴다. Web 출력 변경은 App이 `platforms: ["android", "ios"]`라 해당 없음.
- expo-build-properties: release 빌드에서 R8(코드 축소)이 기본으로 켜진다. 리플렉션을 쓰는 라이브러리는 keep 규칙이 필요할 수 있다.
- expo-dev-client: 개발 빌드를 새로 만든다. launch URL의 `__expo_` 매개변수는 예약.
- Node 22.13+ / 24.3+(지금 24.21).

## Global Constraints

- Expo SDK 58 안에서만 올린다(`npx expo install --fix`가 고르는 버전). 다른 메이저 업그레이드는 하지 않는다.
- `npm audit fix --force`는 쓰지 않는다.
- 공개 API, DB 스키마, 화면은 바꾸지 않는다.
- lock 파일은 저장소 루트에서 `npm install`로 만든다(17주차: `mobile`에서 만들면 `expo-modules-core`가 `node_modules/expo/node_modules`에 들어가 App 테스트가 모두 깨졌다).
- 지우지 않는다. 옛 `mobile/android`와 빌드 캐시는 옆으로 옮긴다.
- 커밋 메시지 English, Task마다 커밋. push는 하지 않는다.

### Task 1: SDK 58 패키지와 코드

- `mobile`에서 `npx expo install expo@^58.0.0 --fix`, 그 뒤 lock 파일을 되돌리고 루트에서 `npm install`.
- `npx expo-doctor@latest`.
- typecheck · lint · App 테스트에서 깨지는 곳을 고친다(동작은 그대로).
- 확인: App 테스트 · lint · typecheck, `npm ls expo-modules-core react react-native`(한 벌씩), `npm audit`(expo-router의 `query-string`, `@expo/fingerprint`의 `minimatch`가 사라짐), Web · Admin 테스트.

### Task 2: 개발 빌드와 release 빌드

- 옛 `mobile/android`를 옆으로 옮기고 `npx expo run:android --no-bundler`(JDK 21)로 새로 만든다.
- 에뮬레이터: 지도 · 마커 · 클러스터 · 미리보기 · 검색 · 상세 · 탐색 · 로그인 · 상태 표시줄.
- release 빌드(R8)를 만들어 에뮬레이터에서 지도와 목록이 뜨는지 본다. 깨지면 keep 규칙을 더한다(끄지 않는다).

### Task 3: 확인과 문서

- 전체 테스트, lint, typecheck, admin 빌드, Web 빌드.
- README의 Tech Stack과 Current Status 18주차, `mobile/README.md`의 SDK 버전.
